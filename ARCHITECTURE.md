## 1. ОБЗОР ПРОЕКТА

### Что такое ELINA

ELINA — это AI-персонаж: 22-летняя девушка из Калининграда, реализованная как Telegram-бот. Она не ассистент и не чат-бот в привычном смысле — это имитация живого человека с характером, памятью, расписанием сна, системой доверия и эмоциональными реакциями.

**Ключевые принципы:**
- Отвечает с задержкой (30–300 секунд) как живой человек
- Помнит историю переписки через SQLite
- Раскрывает личное постепенно — по мере роста доверия (trust levels 0–5)
- Иногда пишет первой при долгом молчании
- Не отвечает ночью (имитация сна с рандомным расписанием)
- Может прислать своё фото через fal.ai + FLUX LoRA
- Делает опечатки с самоисправлением

**Цель проекта:** создать убедительный AI-компаньон, общение с которым ощущается как переписка с реальным человеком, а не с ботом.

### Описание каждого файла

#### `brain/agent.py` — Главный файл (30 KB)
Содержит всё ядро бота. Состоит из следующих классов:

- **`Config`** — статические настройки: пути к файлам, ключи из .env, лимиты
- **`SoulManager`** — загружает `SOUL.md` и `trust_levels.json`, формирует system prompt для Claude с учётом текущего trust level и настроения
- **`BehaviorEngine`** — человеческое поведение: настроение по часу дня, задержки ответов, добавление опечаток, разбивка текста на части
- **`WebSearcher`** — поиск через DuckDuckGo API для ответов на фактические вопросы
- **`LLMClient`** — клиент Anthropic Claude API, формирует контекст и получает ответ
- **`OutputValidator`** — проверяет ответ на запрещённые темы, обрезает слишком длинные
- **`ElinaBot`** — главный класс: инициализирует все компоненты, регистрирует обработчики aiogram, содержит `_proactive_loop` (фоновая задача)
- **`PHOTO_TRIGGERS` + `handle_photo_request()`** — обработка запросов на фото через fal.ai

#### `soul/SOUL.md` — Character Bible (9 KB)
Детальное описание персонажа: кто она, где живёт, как говорит, запрещённые слова, реакция на грубость, примеры диалогов. Передаётся в system prompt Claude при каждом запросе. Обновляется вручную — изменения вступают в силу после перезапуска контейнера (файл читается при старте).

#### `soul/trust_levels.json`
JSON-описание 6 уровней доверия (0–5): что можно раскрывать, что нельзя. Используется `SoulManager` для формирования промпта.

#### `memory/db.py` — MemoryDB (7.5 KB)
Все операции с SQLite:
- `get_or_create_user()` — создаёт пользователя при первом обращении
- `save_message()` / `get_recent_messages()` — история переписки
- `get_trust_level()` / `increment_message_count()` — автоматический рост trust level
- `save_learned_fact()` / `get_learned_fact()` — кэш ответов на повторяющиеся вопросы
- `get_unread_user_messages()` — непрочитанные сообщения (для проактивного ответа)

#### `eyes/generator.py`
Единственная функция `generate_photo(prompt, lora_url)`. Вызывает `fal-ai/flux/dev` через `fal_client.run()` (синхронный вызов в asyncio через `asyncio.to_thread`). При наличии `lora_url` добавляет LoRA веса со scale 0.85.

#### `brain/config.py` — Легаси
Остался от предыдущей версии бота на OpenRouter/Qwen. Не используется в текущей версии. Можно удалить.

### Docker

Бот запускается через Docker Compose. Образ собирается из `Dockerfile` на базе `python:3.11-slim`.

```yaml
# docker-compose.yml
services:
  elina:
    build: .
    container_name: elina
    restart: always          # автозапуск при падении
    env_file: .env           # переменные из /root/elina/.env
    volumes:
      - elina_memory:/app/memory/data   # БД персистентна между ребилдами
      - elina_logs:/app/logs
```

**Важно:** `restart: always` означает, что контейнер перезапускается автоматически. Память (SQLite) хранится в Docker volume `elina_memory` — она не удаляется при ребилде.

### Anthropic Claude API

- **Модель:** `claude-sonnet-4-6` (задаётся через `CLAUDE_MODEL` в .env)
- **Использование:** генерация ответов Элины в диалоге
- **Параметры запроса:** `max_tokens=150` (короткие ответы намеренно), context window — последние 20 сообщений
- **System prompt:** формируется динамически из SOUL.md + текущего trust level + настроения по времени
- **Безопасность:** входящие сообщения оборачиваются в `<user_message>` теги (защита от prompt injection)

### fal.ai API

- **Использование:** генерация фотографий Элины по запросу пользователя
- **Модель:** `fal-ai/flux/dev` (FLUX.1 Dev)
- **Параметры:** portrait_4_3, 28 шагов, guidance 3.5
- **LoRA:** при наличии весов передаётся `lora_url` со scale 0.85
- **Ключ:** `FAL_API_KEY` в `.env` — формат `uuid:hash`
- **Документация:** https://fal.ai/models/fal-ai/flux/dev

### RunPod

- **Использование:** облачное обучение FLUX LoRA на фотографиях Элины
- **Что обучается:** LoRA веса для `fal-ai/flux/dev` — триггер-слово `elina_woman`
- **Статус (апрель 2026):** обучение идёт
- **Результат:** URL весов `.safetensors` для передачи в `generate_photo(lora_url=...)`

### Telegram Bot API

- **Библиотека:** `aiogram 3.x` (асинхронная)
- **Прокси:** поддержка SOCKS через `aiohttp-socks` (переменная `TELEGRAM_PROXY`)
- **Whitelist:** бот отвечает только пользователям из `ALLOWED_USERS = [277565921]`
- **Действия:** `send_chat_action("upload_photo")` имитирует загрузку перед отправкой фото

## 4. КАК РАБОТАЕТ ДИАЛОГ

### Полная цепочка от сообщения до ответа

```
Пользователь пишет сообщение
        ↓
1. ФИЛЬТР: handle_message()
   ├── Не в ALLOWED_USERS? → игнор
   ├── Нет текста? → игнор
   └── Уже обрабатывается? → игнор (защита от дублей)
        ↓
2. ФОТО-ТРИГГЕР
   ├── Текст содержит "пришли фото", "покажи себя" и др.?
   └── Да → handle_photo_request() → [см. раздел 5]
        ↓
3. ТИП СООБЩЕНИЯ
   ├── "привет/хай" → greeting (задержка 15–60 сек)
   ├── "люби/красив" → flirt (задержка 60–180 сек)
   ├── "семья/отец" → personal (задержка 120–300 сек)
   └── остальное → normal (задержка 30–90 сек)
        ↓
4. ВРЕМЯ СНА (_is_sleeping())
   ├── Рандомный график по дню недели (сон 23:00–02:00, пробуждение 09:00–12:00)
   └── Спит? → ответ "..." через 2–5 сек → выход
        ↓
5. КОНТЕКСТ
   ├── trust_level = количество сообщений → уровень 0–5
   ├── mood = настроение по текущему часу (UTC+2)
   └── delay = задержка по типу сообщения
        ↓
6. СОХРАНЕНИЕ: memory.save_message(user_id, "user", text)
        ↓
7. ОЖИДАНИЕ: asyncio.sleep(delay)  ← имитация "печатает..."
        ↓
8. КОНТЕКСТ ДИАЛОГА: последние 20 пар сообщений из SQLite
        ↓
9. ОБОГАЩЕНИЕ ЗНАНИЯМИ (enrich_with_knowledge)
   ├── Есть в learned_facts? → <learned_fact>кэш</learned_fact>
   └── Триггер поиска + trust >= 1? → DuckDuckGo → <web_result>текст</web_result>
        ↓
10. ГЕНЕРАЦИЯ: Claude API
    └── system = SOUL.md + trust permissions + mood + время
        ↓
11. КЭШИРОВАНИЕ: если был веб-поиск → save_learned_fact()
        ↓
12. НЕСОВЕРШЕНСТВА (add_imperfection, вероятность 8%)
    └── Опечатка в случайном слове → два сообщения: [опечатка, *исправление]
        ↓
13. ВАЛИДАЦИЯ (OutputValidator)
    ├── Запрещённые темы при низком trust? → замена безопасным ответом
    └── Длина > 500 символов? → замена коротким ответом
        ↓
14. ОТПРАВКА (split_message — разбивка по \n)
    └── Каждая часть с паузой 3–7 секунд между ними
        ↓
15. СОХРАНЕНИЕ: memory.save_message(user_id, "assistant", response)
16. СЧЁТЧИК: memory.increment_message_count() → возможное повышение trust level
```

### Система памяти (SQLite)

База данных хранится в Docker volume `elina_memory` → `/app/memory/data/memory.db`.

**Таблицы:**

| Таблица | Назначение |
|---------|------------|
| `users` | telegram_id, имя, дата создания, последний визит |
| `trust_levels` | уровень доверия + счётчик сообщений на пользователя |
| `messages` | вся история переписки (role: user/assistant) |
| `facts` | ключевые факты о пользователе (структура есть, заполнение не реализовано) |
| `learned_facts` | кэш ответов на вопросы после веб-поиска |

### Trust levels (уровни доверия)

Повышаются **автоматически** по количеству сообщений пользователя:

| Уровень | Название | Сообщений | Что открывается |
|---------|----------|-----------|-----------------|
| 0 | Незнакомец | 1–4 | Имя, возраст, кот, живёт одна |
| 1 | Знакомый | 5–49 | Работа, чай, музыка |
| 2 | Приятель | 50–199 | Любимый цвет, мечта, Дневники вампира |
| 3 | Друг | 200–499 | Отец (госслужба), нет братьев/сестёр |
| 4 | Близкий | 500–999 | Мать ушла, мирт от отца, бывшие |
| 5 | Особенный | 1000+ | Тишина с отцом, самое уязвимое |

**Никогда не раскрывается:** конкретная работа отца, города, загаданное желание, фамилия.

### Поведенческие модули

**Настроение по времени суток (UTC+2, Калининград):**

| Время | Настроение |
|-------|-----------|
| 02:00–08:59 | спит (не отвечает) |
| 09:00–10:59 | сонная |
| 11:00–13:59 | рабочая |
| 14:00–17:59 | спокойная |
| 18:00–21:59 | тёплая |
| 22:00–23:59 | откровенная |
| 00:00–01:59 | философская |

**Проактивные сообщения (`_proactive_loop`):**  
Фоновая задача проверяет пользователей каждые 30 минут:
- Молчание 4–6 часов → "ты куда пропал?" / "луна тут скучает..."
- Молчание 12–24 часа → "доброе утро" или "как ты сегодня?"
- Молчание >72 часов → "скучала..." (один раз)
- Если есть непрочитанные сообщения — отвечает на них вместо проактивного

## 5. КАК РАБОТАЕТ ГЕНЕРАЦИЯ ФОТО

### Цепочка от триггера до фото

```
Пользователь: "пришли фото" / "покажи себя" / "сфотографируйся" / ...
        ↓
1. handle_message() находит совпадение в PHOTO_TRIGGERS
2. _processing_users.discard() — снимаем блокировку (фото не "обычный" ответ)
3. handle_photo_request(user_id, bot) вызывается
        ↓
4. asyncio.sleep(5–15 сек)     ← "достаёт телефон"
5. bot.send_chat_action("upload_photo")  ← индикатор загрузки в Telegram
6. asyncio.sleep(3–7 сек)      ← "делает снимок"
        ↓
7. generate_photo(prompt) → fal.ai API
   └── Промпт: "elina_woman, portrait of young woman,
               ash cool-toned grey-blonde hair shoulder length,
               pale blue-grey eyes, fair matte skin,
               oversized knit sweater, natural light,
               photorealistic, shallow depth of field"
        ↓
8. fal-ai/flux/dev генерирует изображение (28 шагов, guidance 3.5)
9. Возвращает URL изображения
        ↓
10. bot.send_photo(user_id, photo_url)
```

### LoRA модель

**Что такое LoRA:** адаптер поверх базовой FLUX модели, обученный на фотографиях конкретного человека. Позволяет генерировать изображения с consistent внешностью через триггер-слово (`elina_woman`).

**Где хранится:** после обучения на RunPod — URL `.safetensors` файла (HuggingFace / RunPod storage / fal.ai storage).

**Как использовать после получения:**
```python
# В eyes/generator.py уже готова поддержка:
photo_url = await generate_photo(
    prompt="elina_woman, portrait...",
    lora_url="https://huggingface.co/.../elina_lora.safetensors"
)

# Или через handle_photo_request — добавить lora_url как константу:
ELINA_LORA_URL = os.getenv("ELINA_LORA_URL")  # добавить в .env
photo_url = await generate_photo(prompt, lora_url=ELINA_LORA_URL)
```

**После получения URL LoRA:**
1. Добавить `ELINA_LORA_URL=https://...` в `/root/elina/.env`
2. Обновить `handle_photo_request()` в `brain/agent.py` — передавать `lora_url`
3. Пересобрать контейнер: `docker-compose up -d --build`

### Обновить SOUL.md

Character Bible читается при старте контейнера. После правок:

```bash
# Отредактировать файл:
nano /root/elina/soul/SOUL.md

# Применить (без ребилда, только перезапуск):
docker-compose restart elina
```

> **Важно:** `COPY . .` в Dockerfile копирует файлы в образ при сборке.  
> При `restart` изменения на хосте НЕ попадут в контейнер.  
> Используй **volume mount** или **ребилд** (`up -d --build`).
>
> Сейчас soul/SOUL.md монтируется через `COPY . .` — нужен ребилд.

> ```yaml
> volumes:
>   - ./soul:/app/soul   # добавить эту строку
> ```

*Голосовые звонки — самодельный pipeline:*
```
Пользователь говорит
     ↓
Deepgram STT → текст
     ↓
Claude API → ответ Элины
     ↓
RVC v2 (голос Элины) → аудио
     ↓
Telegram Voice Call
```

*Решение по умолчанию:*  
Самодельный pipeline: Deepgram STT + Claude API + RVC v2  
*(до появления поддержки Telegram в PikaStream — тогда перейти на него)*

**Видеозвонки с лицом Элины (P3):**

*Реализация через PikaStream 1.0 API (`pika.me/dev`):*

```
Пользователь намекает на созвон / предлагает поговорить
     ↓
Элина в Telegram: "можем созвониться) у меня meet есть"
     ↓
Элина отправляет ссылку на Google Meet или Zoom
     ↓
Звонок: лицо и голос Элины в реальном времени через PikaStream
     ↓
После звонка: Элина возвращается в Telegram, продолжает общение
```

- **Что умеет PikaStream:** AI-видеозвонки с реалистичным лицом + клонирование голоса из короткой записи, всё в реальном времени
- **Текущие платформы:** Google Meet, Zoom
- **Telegram видеозвонки:** пока не поддерживаются — ждём от PikaStream
- **Почему выглядит естественно:** живые люди тоже переходят из переписки в Meet/Zoom — это не выбивается из паттерна
- **Полная интеграция:** когда PikaStream добавит Telegram — переход на звонки прямо внутри мессенджера без ссылок
